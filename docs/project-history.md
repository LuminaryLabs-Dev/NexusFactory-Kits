# Project history

This timeline reflects the repository's **existing recorded milestones**, primarily `CHANGELOG.md`, not a reconstructed release calendar.

| Date / milestone | Evidence recorded in the repository |
| --- | --- |
| 2026-08-19 | Initial semantic domain/capability graph, registry, Ballista and Tree Kits, tests and demo |
| 2026-08-20 | Coral Generator, editor contracts, PNG/raster utilities and validation tooling |
| 2026-08-21 | Phased Tree runtime and standardized export contracts |
| 2026-08-22 | Layered aquatic raster generators, Reef and Aquarium scene compositions, live registry |
| 2026-08-24 | Core architecture, contracts, catalog, development, validation and agent documentation; fish work |
| 2026-08-25–26 | Coral morphology/style and Aquatic Flora redesign evidence, with selected review variants |
| 2026-09-05 | Three procedural horror-related factories: creatures, liminal corridors, distressed surfaces |
| Unreleased work | Triceratops mesh editor, offline 3D coral export pipeline, standalone amethyst factory and associated review evidence |

The root `package.json` currently declares **0.1.0**; individual public Kit versions vary and should be read from the registry/manifests rather than inferred from that package version. The existing README enumerates **11 public Kits**. Earlier validation notes describe eight-Kit snapshots; do not reinterpret those earlier counts as the current catalog.

## Ownership and related repositories

- **NexusFactory-Kits** owns generator meaning, input contracts, seeded execution, artifact validation and export.
- **NexusFactory-Studio** owns the generic registry-driven browser interface and preview/download experience. See [Studio handoff](studio-handoff.md).

## Evidence boundaries

`CHANGELOG.md` and `docs/validation.md` record historical source/test/review results. This documentation pass did not rerun those checks or independently verify production deployment, generated-art rights, live CDN behavior, visual acceptance, or Steam/game release readiness.

See [the changelog](../CHANGELOG.md), [validation](validation.md), and [known issues](known-issues.md) before describing any milestone as completed product acceptance.
